# Admin and Super Admin User Guide

Administration, Control, and Configuration

Version 1.0

Prepared: 31 March 2026

Audience:

- administrators
- super admins
- system control users
- configuration and governance owners

## 1. Purpose

This guide explains the administrative and governance workspaces used to manage access, configuration, workflows, audit, and system operations.

## 2. Main Workspaces

Administrative users will mainly use:

- Settings
- Audit
- BankingOS Control
- Products
- Workspace Views
- Reporting
- Security Ops
- End of Day

## 3. Core Responsibilities

Admin and super-admin users may be responsible for:

- user and role administration
- branch administration
- privilege lease control
- system configuration
- workflow and product governance
- audit review
- operational signoff and oversight

## 4. Settings and Access Control

Typical administration tasks:

- create or update users
- assign roles
- manage branches
- grant or revoke privilege leases
- review configuration flags

## 5. Configuration Governance

Administrative users should:

- change only clearly understood settings
- document sensitive changes through notes or change control
- validate downstream impact after major config changes

## 6. BankingOS and Workflow Control

Use BankingOS and related control workspaces for:

- process catalogs
- form catalogs
- bundles
- workflow tasks
- product rules
- runtime workflow operations

## 7. Product Administration

Product-related activities may include:

- reviewing product definitions
- checking amount ranges
- validating currency context
- updating governance rules

## 8. Audit Review

Use the audit workspace to:

- inspect who changed what
- review failed or suspicious operations
- investigate operational incidents

## 9. Security and Compliance Oversight

Use security operations to review:

- alerts
- failed logins
- sessions
- devices
- suspicious activity

## 10. End-of-Day Oversight

Administrative or supervisory users may need to:

- inspect EOD status
- run or re-run a step if authorized
- monitor job results
- review scheduled operational jobs

## 11. Reporting for Oversight

Use reporting to monitor:

- branch posture
- operational performance
- exceptions
- portfolio and finance summaries

## 12. Best Practices

- Apply least privilege wherever possible.
- Review changes before saving high-impact configuration.
- Use audit trails to validate sensitive actions.
- Confirm role and permission impact after access changes.
- Treat workflow, product, and system settings as controlled changes.

## 13. Escalation Guidance

Escalate when:

- a user requires access beyond normal policy
- a workflow change has unclear impact
- repeated unauthorized or suspicious events appear
- an operational job fails and the cause is unclear
